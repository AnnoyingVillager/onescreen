# OneScreen 范围与验收标准

## 产品目标

在世界中的一个方块位置显示一块可配置尺寸的图片/视频屏幕。屏幕内容由服务器保存的 URL 决定，客户端异步解析和播放媒体，并可从屏幕位置输出声音。

## 第一版用户流程

1. 管理员获得或生成一个屏幕方块并放置到世界中。
2. 管理员执行命令设置屏幕 URL。
3. 服务端校验 URL 并保存到方块实体。
4. 跟踪该方块的客户端收到数据并异步加载媒体。
5. 客户端渲染屏幕并按照距离播放声音。
6. 玩家离开区块后媒体资源释放；返回后重新加载。

## 功能要求

### 方块

- 单一 `screen` 方块。
- 支持水平四向朝向。
- 具有可掉落物品、模型、本地化名称和基础碰撞。
- 方块的视觉面积可以超过一个方块，但第一版不要求占用多个碰撞方块。

### 配置数据

- URL。
- 屏幕宽度，单位为方块。
- 屏幕高度，单位为方块。
- 音量 `0.0–1.0`。
- 静音状态。
- 是否循环。

### 媒体

- 图片、视频和媒体声音统一由 WATERMeDIA 3 管理。
- 图片和视频使用同一屏幕渲染入口。
- 媒体解析、下载和解码必须异步。
- 错误 URL 显示占位状态，不得导致客户端崩溃。

### 同步

- 服务端是 URL 和屏幕配置的唯一权威。
- 第一版通过方块实体更新包同步 URL，不额外实现客户端编辑网络协议。
- 玩家进入区块时通过 `getUpdateTag` 获得当前配置。

### 命令

- 仅管理员可修改屏幕。
- 命令应验证目标位置确实存在屏幕方块。
- 命令返回明确的成功或失败消息。

## 非功能要求

- 客户端或服务端均能安全启动。
- 不在 `src/main` 引用客户端类。
- 每个屏幕最多一个活动媒体会话。
- 单客户端默认最多同时打开 4–8 个媒体会话。
- 离开区块、切换维度或断线时释放资源。
- 不依赖 Mixin 或 access widener。
- 默认兼容 OpenGL 路径，并为 26.2 图形后端保留后端无关的媒体纹理接口。

## 明确不包含

- GUI 编辑器。
- 播放列表。
- 遥控器。
- 上传和搜索功能。
- 多方块结构或无缝拼接。
- 任意三维旋转。
- 文件服务器、代理服务器或媒体转码。
- 复杂权限系统和按玩家差异化 URL。
- WaterVision、Valkyrien Skies、Sable 等第三方集成。

## 完成定义

第一版可以发布的最低条件：

- `compileJava`、`runClient` 和 `runServer` 成功。
- 图片、视频和声音在单人游戏中通过验收。
- 两个客户端可以看到同一 URL 并独立计算音量。
- 离开区块和断线后资源会被释放。
- URL 在保存并重进世界后保持一致。
- 非法 URL、超长 URL 和不存在的位置不会抛异常。
- 客户端日志、服务端日志和旧存档测试均通过。
