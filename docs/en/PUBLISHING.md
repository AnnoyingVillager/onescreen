# Publishing

## Current version status

- Latest public release: `0.2.1`.
- Current source version: `0.2.1`, corresponding to GitHub release tag `v0.2.1`.
- Tag format: `v<version>`, for example `v0.2.1`.
- The tag version must exactly match `version` in `gradle.properties`.

Before a release, confirm or update:

- `version` in `gradle.properties`.
- The version entry in `CHANGELOG.md`.
- Public version and compatibility statements in `README.md` and `README.en.md`.
- `.github/release-notes/v<version>.md`, when needed.
- Keep `fabric.mod.json` using the Gradle placeholder `"${version}"`; do not hard-code the version.

## Local build

Windows PowerShell:

```powershell
$env:JAVA_HOME='C:\Users\user\AppData\Roaming\.minecraft\runtime\java-runtime-epsilon'
$env:GRADLE_USER_HOME='E:\waterframes\.gradle-user-home'
.\gradlew.bat build --rerun-tasks --offline --no-daemon --no-configuration-cache
```

When using a system JDK 25, `JAVA_HOME` and `GRADLE_USER_HOME` can be omitted. Release builds should use `--rerun-tasks` to avoid reusing stale packaging output.

Expected artifacts:

```text
build/libs/onescreen-<version>.jar
build/libs/onescreen-<version>-sources.jar
build/libs/onescreen-<version>.sha256
```

The `.sha256` file is generated by the release workflow. Locally, verify the JARs with PowerShell:

```powershell
Get-FileHash 'build\libs\onescreen-0.2.1.jar' -Algorithm SHA256
Get-FileHash 'build\libs\onescreen-0.2.1-sources.jar' -Algorithm SHA256
```

The JAR must contain at least:

- `fabric.mod.json`
- `LICENSE`
- `assets/onescreen/lang/*.json`
- Common/server classes from `src/main`
- Client classes from `src/client`
- `onescreen.client.mixins.json` and all three Vulkan Mixins

Never include or commit:

- `run/`, `logs/`, crash reports, or worlds.
- `.gradle/`, `build/`.
- Downloaded WATERMeDIA Binaries.
- Local test media, temporary `.codex-*` scripts, or private URLs.
- Local usernames, tokens, private keys, or personal absolute paths.

## GitHub Actions

### `build.yml`

- Runs on every push, pull request, and manual dispatch.
- Uses Temurin Java 25.
- Uploads `build/libs/*.jar` excluding `*-dev.jar` as 14-day test artifacts.

### `release.yml`

- Runs only when a `v*` tag is pushed.
- Forces `build --rerun-tasks`.
- Verifies the tag version matches `gradle.properties`.
- Creates SHA-256 files for the main JAR and sources JAR.
- Uses `GITHUB_TOKEN` to create a GitHub Release with all three files.

The workflow runs shell commands on Ubuntu. Local development and Agent operations must still use PowerShell. The CI shell does not change the local execution policy.

## Create a release tag

Only run this after the user explicitly requests a release:

```powershell
git tag -a v0.2.1 -m 'OneScreen 0.2.1'
git push origin main
git push origin v0.2.1
```

Pushing the tag triggers `.github/workflows/release.yml`. If the tag and project version differ, the workflow must fail without creating a Release.

## Pre-release checklist

- [ ] `gradlew build` passes and the working tree has no accidental temporary files.
- [ ] Java 25, Minecraft 26.2, Fabric API, and WATERMeDIA 3.0.0 statements agree across README files.
- [ ] OpenGL 1080p/4K regression is complete.
- [ ] Vulkan 1080p/4K regression is complete.
- [ ] All three Vulkan queue-sync Mixins are injected with no device loss.
- [ ] Pause, stop, refresh, loop, VOD seek, and HLS progress regressions pass.
- [ ] README.md, README.en.md, CHANGELOG, release notes, and human documentation are synchronized.
- [ ] `agents/` status, test results, and next tasks are synchronized.
- [ ] The JAR contains no private URL, log, Binaries, or runtime world.
- [ ] Release assets contain the main JAR, sources JAR, and SHA-256 file.

## Secrets and permissions

The release workflow uses only the GitHub-provided `GITHUB_TOKEN`. Normal builds have `contents: read`; the release job has `contents: write`. Never store PATs, passwords, or private keys in the repository.
